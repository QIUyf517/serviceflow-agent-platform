# ServiceFlow 3 分钟演示脚本

本脚本面向面试或作品集录屏。目标不是展示所有页面，而是在三分钟内证明“Agent 能安全完成业务动作，并且过程可追溯”。

## 准备

先按 [本地开发指南](LOCAL_DEVELOPMENT.md) 启动并导入模拟数据。确认以下地址可访问：

- 商城：<http://127.0.0.1:5173/store>
- 管理后台：<http://127.0.0.1:5173/admin>
- 开发者页：<http://127.0.0.1:5173/developer>

仅使用 τ-bench 提供的模拟账户。不要在录屏、截图或提交记录中出现真实邮箱、地址、支付信息、`.env.phase4` 或操作员 Token。

## 0:00–0:35｜产品入口与身份边界

1. 打开商城，展示商品目录来自业务数据库。
2. 未核验身份时指出：商品公开，但订单区域不会显示任何客户资料。
3. 使用本地模拟账户完成核验，展示“我的订单”。

要说明的重点：前端提供的订单号不能授权访问，订单归属由服务端会话身份决定。

## 0:35–1:25｜取消订单的确认门

1. 在一笔 `pending` 模拟订单中点击“联系商家客服”。
2. 输入“这个订单不要了”。
3. 展示系统返回的具体操作摘要和“订单尚未修改”。
4. 先切回订单列表，证明订单仍是待处理状态。
5. 返回客服输入“确认”，等待服务端成功结果。
6. 展示商城中的订单状态同步变为已取消。

要说明的重点：模型只能理解意图；客户确认后，服务端仍会重新读取订单、加锁并执行确定性规则。

## 1:25–2:10｜人工接管

1. 在另一笔订单中请求“转人工”，创建工单。
2. 打开管理后台，在当前标签页输入本地操作员 Token。
3. 展示工单、脱敏订单摘要和审计事件，发送一条人工回复。
4. 回到顾客窗口，展示同一工单中的回复。

要说明的重点：人工审批不能代替客户确认；人工触发写动作也必须满足同一执行边界。

## 2:10–2:45｜开发者追踪

1. 打开开发者页。
2. 展示刚才操作的 `trace_id`、Agent 节点、工具调用、耗时和结果。
3. 指出 Provider 为 Mock 时页面会明确标识，不会伪装成真实模型调用。

## 2:45–3:00｜用测试结果收尾

可以这样总结：

> 这个项目的重点不是 Agent 数量，而是把身份、授权、确认、事务、幂等、审计和恢复做成独立可测的服务端边界。完整后端回归 269 项通过；冻结保留集上多 Agent 没有战胜单 Agent，所以我保留了负结果，而没有只展示开发集最好成绩。

## 无外部 LLM 的演示方式

Compose 默认使用 Mock/本地规则模式，取消、退货、政策查询、人工接管和追踪均可演示，不需要付费 API。配置外部兼容模型后，它只补充意图理解，不获得业务授权或数据库写权限。

## 演示后清理

普通停止不会删除数据库卷：

```powershell
docker compose down
```

只有确定不再需要本地演示数据时，才显式删除卷：

```powershell
docker compose down --volumes
```
